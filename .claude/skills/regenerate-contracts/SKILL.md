# Regenerating generated type contracts

## Overview

`apps/backend/cmd/typegen` is the single producer of
`apps/frontend/src/shared/contracts/{enums,errors,dto,ws,index}.ts`. Nothing under
`apps/frontend/src/shared/contracts` is hand-edited — files carry a
`// Code generated by cmd/typegen. DO NOT EDIT.` header. Full rationale:
`ObsidianVault/contratos-tipos-generados.md`.

## Regenerate

From `apps/backend` (host — `cmd/typegen` imports no networking, isn't affected by this
machine's Application Control block on `go test` binaries):

```
make types           # writes the files
make types-check      # fails (names the stale file) without writing, for CI-style checks
```

Docker fallback (same App-Control workaround as `test-docker`):

```
make types-docker
make types-check-docker
```

After regenerating, `git diff -- apps/frontend/src/shared/contracts` and commit the result — a
new/changed generated file with nothing else changed is expected and correct. Then re-run the
frontend suite: the regenerated types may no longer compile against the hand-written form schemas
that compose them (stand/devil-fruit/stage forms, translation `superRefine`s). Full check sequence
(what changed backend paths imply, when contracts also need frontend re-verification): see
`.claude/skills/verify/SKILL.md` §4.

## Adding a new wire type

| Change | Steps |
|---|---|
| New enum | `type X byte` in `internal/domain/enums/`, register in `WireEnums` (`registry.go`) — `registry_test.go` fails without it. `make types`. |
| New member on existing enum | Add to the `iota` block + `String()` + `IsValid()` + `ParseX` (+ Postgres migration if persisted), and add it to `WireEnums`'s member list. Forgetting the `WireEnums` entry fails `registry_test.go` with the exact ordinal `IsValid()` accepts but `WireEnums` doesn't list. |
| New DTO | Struct in `internal/infrastructure/api/dto`, register in `cmd/typegen/registry.go` (`restTypes` or `wsOnlyTypes`) — an AST-scan test fails on any exported `dto` struct that's registered nowhere. Add `ts:"EnumName"` tags on fields that are wire enums (plain `string`/`[]string`/`map[string]T` fields stay `z.string()` without a tag). |
| New WS command/frame | Constant in `dto/game_ws.go`, the payload struct if it carries one, and an entry in both `FramePayloads`/`CommandPayloads` — `frame_table_test.go` requires they match the `Frame*`/`Command*` constant sets exactly. |
| New error code | Declare as a constant in `internal/infrastructure/api/apierr` (not a literal in a `switch`) — the generator enumerates `apierr.Codes`. |

Run `make types` after any of the above, then `go test ./...` — the registry/completeness tests
above catch a forgotten registration before typegen ever runs.

## Common mistakes

- Editing a file in `shared/contracts/` by hand — it's overwritten on next `make types` and CI's
  `contracts` job (regenerates twice, fails on `git diff` or a new untracked file) will catch the
  drift anyway.
- Reordering Go struct fields "for tidiness" — the generator preserves Go declaration order on
  purpose, so a real change stays a small diff.
- Forgetting the registry/table entry (`WireEnums`, `restTypes`/`wsOnlyTypes`,
  `FramePayloads`/`CommandPayloads`, `apierr.Codes`) — this is caught by `go test`, not by
  `make types` itself, which will just silently omit the new member/type.
